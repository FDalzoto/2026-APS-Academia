## Atores

Três papéis usam o GestãoFitPro. O ator representa o papel que utiliza o sistema, e não uma pessoa específica. Conforme definido na Seção 4.1, os atores são Aluno, Instrutor e Atendente.

O ator é quem opera o sistema para alcançar um objetivo. O Atendente cadastra os alunos e registra os pagamentos, enquanto o Instrutor registra e atualiza os treinos e o Aluno consulta seu treino atual.

| Ator | Quem é | O que faz no sistema |
|---|---|---|
| Aluno | Pessoa matriculada na academia | Consulta seu treino atual, seu plano e o histórico dos treinos realizados. |
| Instrutor | Profissional responsável pelos treinos dos alunos | Consulta os dados dos alunos e registra ou atualiza seus treinos. |
| Atendente | Pessoa responsável pelo atendimento da academia. | Cadastra os alunos, registra pagamentos e acompanha as mensalidades atrasadas e os planos próximos do vencimento. |

## Especificação do caso de uso principal

<!-- Escolha o caso de uso que o sistema existe para fazer.
     Pré-condição: o que precisa ser verdade antes. Pós-condição: o que fica verdade depois.
     Fluxo principal: passos numerados, indo e voltando (o ator informa, o sistema responde), um verbo por passo, sem tela nem botão.
     Alternativo: outro caminho que ainda chega ao fim. Exceção: o caso termina sem a pós-condição. -->

Registrar pagamento foi escolhido como caso de uso principal por estar diretamente relacionado ao problema apresentado pelo responsável pela academia: a dificuldade de controlar as mensalidades e identificar os pagamentos pendentes.

| Campo | |
|---|---|
| Caso de uso | Registrar pagamento |
| Ator | atendente |
| Pré-condição | O aluno está cadastrado no sistema (RF01), e o atendente está autorizado a alterar informações de pagamentos (RNF02). |
| Pós-condição | O pagamento foi registrado no sistema, conforme o RF03. |

**Fluxo principal**

1. O atendente identifica o aluno cujo pagamento será registrado.
2. O sistema apresenta os dados do aluno e as informações da mensalidade correspondente.
3. O atendente informa os dados do pagamento recebido.
4. O sistema verifica as informações fornecidas.
5. O sistema registra o pagamento.
6. O sistema confirma que o pagamento foi registrado.

**Fluxo alternativo**

- **A1, no passo 2: o aluno possui mais de uma mensalidade pendente.** O sistema apresenta as mensalidades correspondentes para que o atendente selecione aquela cujo pagamento será registrado. Após a seleção, o fluxo retorna ao passo 3. Essa situação deverá ser confirmada com o responsável pela academia.

**Fluxos de exceção**

- **E1, no passo 4: as informações do pagamento são inválidas ou insuficintes** O sistema informa que não foi possível registrar o pagamento e solicita a correção das informações. O pagamento não é registrado, e o caso de uso termina sem a pós-condição.

| Requisito | Caso de uso | Onde aparece |
|---|---|---|
| RF01 — Cadastrar aluno | Cadastrar aluno | Elipse do diagrama e pré-condição de Registrar pagamento. |
| RF02 — Cadastrar plano | Nenhuma elipse atualmente | Local a definir, pois o requisito representa uma funcionalidade independente. |
| RF03 — Registrar pagamento | Registrar pagamento | Elipse do diagrama e especificação do caso de uso principal. |
| RF04 — Identificar atrasos | Identificar atrasos | Elipse do diagrama. |
| RF05 — Informar vencimentos | Informar vencimentos | Elipse do diagrama. |
| RF06 — Registrar treino | Registrar treino | Elipse do diagrama. |
| RF07 — Atualizar treino | Nenhuma elipse atualmente | Local a confirmar na especificação de Registrar treino ou em uma revisão do diagrama. |
| RF08 — Consultar treino |  Consultar treino | Elipse do diagrama. |

Os requisitos RF01, RF03, RF04, RF05, RF06 e RF08 possuem casos de uso correspondentes, enquanto RF02 e RF07 ainda precisam ser definidos. A análise identificou pendências no cadastro de planos, na atualização de treinos, na consulta do plano atual, no histórico de treinos e nas funções administrativas. É necessário revisar os requisitos e alinhar as seções 4.1, 4.2.1 e 4.2.2 para garantir a rastreabilidade e a consistência do sistema.
